The idea

Less terminal juggling.
More useful work.

Meringue sits above the coding harnesses you already use. It gives you one chat, one tree, and one stream of useful updates while agents work in their own spaces.

It does not replace your agent. It coordinates the work around it.

What you get

A calm layer over
parallel work.

01

One chat

Describe a goal in plain English. A head agent turns it into an issue and gets the right worker moving.

02

An agent tree

Projects, issues, and workers stay visible in a simple filesystem-like hierarchy. Nothing gets lost in a tab.

03

Real isolation

Workers get their own worktrees and branches. Parallel work stays parallel and your checkout stays safe.

04

Your harness

Use Pi, Claude Code, or Codex CLI. Meringue keeps the core product independent of any one backend.

Install and run

The fastest path from an empty terminal to a working dashboard.

curl -fsSL https://raw.githubusercontent.com/
jackson-lafrance/meringue/main/install.sh | sh
meringue

The installer uses ~/.meringue and ~/.local/bin. Re-run it to update.

01

Core workflow

Chat → issue → worker → useful result. Follow-ups continue the same goal.

02

Commands

/help, /tree, /jump, /worker pause, and more when you want precise control.

03

Configuration

Choose harnesses, models, themes, workspaces, and keybindings in /config.

04

Troubleshooting

Run meringue doctor first. It checks Ruby, Git, your harness, configuration, and state.

Built to stay useful

Simple at the surface.
Extensible underneath.

Meringue stores its state as readable JSON, keeps harness-specific behavior behind a small interface, and leaves the kernel in charge of orchestration. The pieces are inspectable, replaceable, and yours.
